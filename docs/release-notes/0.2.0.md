# Capture Studio 0.2.0 (draft)

> Draft: not released. Live on GNOME Wayland (2026-11-08): W11, W12, W13 and G pass; W14 passes
> its no-hardware case (the case with a working hardware encoder needs another machine); W1
> passes with the camera latency correction (camera ↔ mic −34.5 ms by claps with the first model;
> the current model is not yet checked live, see Known limits).

The teaching editor: layouts that change over time, annotations, zoom and pan, transitions,
speed, audio cleanup, more export formats, and new ways to record. Projects from 0.1.0 open and
are upgraded on the first save; 0.1.0 opens 0.2.0 projects read-only.

## Editor

- **Face layout over time.** Keyframes with easing for the face overlay, and whole stretches as
  full screen, side by side or hidden. Face crop and zoom, border and shadow.
- **Background.** A colour, gradient or picture behind the screen, with padding, rounded corners
  and a shadow.
- **Zoom and pan.** Zoom into part of the screen for a stretch of time, with eased moves in and
  out, or set camera keyframes by hand.
- **Annotations.** Text and titles (four bundled open-licence fonts), arrows, rectangles,
  ellipses, numbered steps, highlights and spotlights, each with in and out times and fades.
  Blur and pixelate regions hide passwords and personal data, and can follow a moving target.
  Everything is editable on the preview.
- **Time.** Speed from 0.25× to 4× with the pitch kept, freeze frames, fade-to-colour,
  cross-dissolve and slide transitions, and markers that become chapters in the exported MP4.
- **Audio.** Clip gain and fades, volume keyframes, noise reduction (measured from the
  recording's own noise floor), loudness normalized to −16 LUFS, and ducking of the system audio
  under the voice. "Cut pauses" proposes the silent stretches; you choose which to cut, and each
  cut can be undone on its own.
- **Media.** Import pictures, video and audio; add a take from another recording; recordings
  larger than 1080p get a 720p proxy for smooth preview (the export still uses the original).

## Export

- MP4 (H.264 or HEVC), WebM (VP9 or AV1), animated GIF (a palette made from the whole clip and a
  choice of dither), and audio only as M4A, Opus or MP3.
- Presets: YouTube 1080p, Small GIF, Web (VP9), Archive (HEVC), Podcast (MP3).
- Save the preview's frame as a PNG.
- Advanced FFmpeg options for experts, checked so they cannot change the inputs, the mapping or
  the output file.
- "Require the hardware encoder": fail instead of quietly using the software one.
- Projects that use the new visuals are exported by rendering each frame with the same
  compositor as the preview, so what you see is what you get.

## Recording

- **Window** recording: pick one window; if it is resized, the recording keeps its size and
  shows the window whole with black bars.
- **Audio only**: microphone and system audio, no picture and no screen-sharing dialog.
- **Stop after** a fixed time (pauses not counted); the controls timer counts down.
- **Record only the region**: smaller files when the rest of the screen is never needed.
- **When done → Export a small GIF**: a quick GIF straight into the exports folder.
- **Require a hardware encoder** for recording.
- **Pack… / Unpack…** in the library: a project as one zip to share (without the regenerable
  cache), and back.

## Automation

The MCP server (for AI assistants) gains tools for the new edits: layouts, background and zoom,
annotations, speed, freeze frames, transitions, markers, clip audio, volume keyframes, audio
cleanup, and export formats and presets. Importing media is not offered to assistants, since it
would let them copy any file into a project.

## Known limits

- Noise reduction "Strong" uses FFmpeg's `afftdn` at a higher setting, not the RNNoise model
  the plan named: the model's licence still has to be checked before it can be bundled.
- Pictures are imported as one-frame videos, so their transparency is lost.
- "Add a take" copies another recording into the project; it does not record into the open
  project.
- The preview is not loudness-normalized (the export is).
- Camera ↔ microphone sync: webcam frames are now moved earlier by the camera's capture latency
  (one frame, at most 33 ms), recorded per project and shown in the inspector. Before it, live W1
  measured 79.4 ms (limit 60 ms). One live check of an earlier, larger correction measured
  −34.5 ms; the current model would have given about 0 ms on that recording but has not been
  re-checked live.
- "Require a hardware encoder" is checked live only on a machine without a working one (it
  refuses to record, as it should).

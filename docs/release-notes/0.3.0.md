# Capture Studio 0.3.0 (draft)

Licensed under GPL-3.0-or-later. **Linux** (GNOME on Wayland and X11) is the tested platform.
**Windows 10/11 and macOS 13+ are a preview:** they build, pass the automated tests on GitHub's
runners, and their packaged app starts there. They have not been installed or used to record on
a real Windows PC or Mac yet (`docs/platform-test-backlog.md`). Projects from 0.2.0 open and are
upgraded on the first save (format 3). 0.2.0 opens 0.3.0 projects read-only (checked with 0.2.0's
own project parser).

## Cursor effects

- **Cursor track.** Recordings on X11, Windows and macOS keep the pointer's path and clicks
  (`media/cursor.jsonl`, 120 Hz) through a small native helper. Without it, the position is
  sampled without clicks. Wayland gives apps no pointer position, so there is no track there.
  On Windows and macOS the track is not yet checked on a real machine.
- **In the editor:** click rings and a highlight around the pointer, the same in the preview and
  the export. Smoothing, a larger cursor and hiding it are there too, but only for recordings
  whose picture does not already show the system cursor. Every recording so far shows it,
  because the recorder cannot yet leave it out, so the editor greys these out with the reason.
- **Auto-zoom on clicks** proposes camera zooms around your clicks. Keep, change or delete each
  one; the whole proposal is one undo step.
- **Live highlighter** (off by default): a circle around the pointer drawn on screen while
  recording a screen or region, and so recorded into the picture for good.
- Assistants (MCP) get `set_cursor_effects` and `auto_zoom`.

## Recording

- **Draw the region on the screen.** On X11, Region mode lets you drag the region over the live
  desktop of the monitor you record (Windows and macOS: built, not yet checked). While recording,
  a dashed frame shows what is recorded. Wayland keeps the frozen-frame picker.
- **All screens.** With several monitors, the source picker on X11 and Windows offers every
  monitor in one picture (checked on X11 with one monitor; two monitors not yet).
- **Window recording** from the in-app window list on X11, Windows and macOS (checked on X11).
- **Wayland:** the screen you shared is reused for the next recordings while the app runs, so the
  system picker appears once per session (after a restart it asks again). Diagnostics →
  "Choose the screen again" asks on the next recording. Not yet checked live on GNOME.
- **Windows and macOS (preview, not yet checked):** system audio is recorded with the screen,
  and the hardware encoders are probed for export (NVENC, Quick Sync and AMF on Windows,
  VideoToolbox on macOS).
- **macOS permissions:** the setup panel says which permissions are missing and what each is for,
  opens the right pane in System Settings, and notices changes when you come back. Recording the
  screen waits for Screen Recording permission; audio only does not. Tested with a simulated Mac.

## Packages and updates

- Linux: AppImage and deb, as before.
- Windows (preview): an installer for one user (`capture-studio-setup-0.3.0-x64.exe`).
- macOS (preview): dmg and zip for Apple silicon and Intel.
- `.cstudiopack` files (Pack…) are registered with the app on every system, so a double-click
  should open them (opening a pack given on the command line is tested; the double-click itself
  is not yet). On macOS a `.cstudio` project is one document in Finder.
- **Updates** from this project's GitHub Releases, with a Releases or Pre-releases channel in
  Settings. The Windows installer and the AppImage are set up to update themselves; this is
  tested against a simulated updater only, since no release has been published to update from.
  The deb updates through the package manager. Unsigned Mac builds cannot update themselves.

## Known limits

- Windows and macOS builds are unsigned for now: Windows shows a SmartScreen warning, macOS a
  Gatekeeper warning. macOS also asks for its permissions again after every update.
- Until hiding windows from captures is checked on a real machine (Windows) or known to work
  (macOS 15 and later), the controls minimize when recording starts there.
- macOS system audio is not verified. A recording without system audio says so and continues.
- Hiding the cursor from the recording itself is not available yet on any system.
- The region picker over the live desktop needs a compositing window manager on X11 (GNOME and
  KDE have one).
- A recording recovered after a crash keeps its video and audio but not its cursor track.
- The live highlighter does not show with "All screens", and the frozen-frame picker is used for
  a region over all screens.
- On Linux the recording frame cannot be hidden from the capture. It sits just outside the
  region, so it stays out of the cropped picture, but it is in the full frame of a region
  recording that was not cropped at record time.

## Verification

Linux, automated: unit, integration and end-to-end tests (Xvfb, X11). They cover recordings with
a cursor track and clicks, the on-screen region picker, frame and highlighter, "All screens", the
macOS permission guidance with a simulated Mac, and a smoke check of every capability the app
reports as available. The packages built and passed their smoke tests on all four CI runners
(Linux, Windows, macOS arm64 and x64). Not yet done: the live GNOME check of the reused screen,
the click-timing check (spike S11), and everything in `docs/windows-manual-checklist.md` and
`docs/macos-manual-checklist.md`.

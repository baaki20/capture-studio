# P3 spikes S9 (Windows), S10 (macOS), S11 (cursor clock) — waiting for the test machines

Harness: `spikes/p3-platform/` (throwaway). On the Windows or macOS machine, from a checkout of
`phase3` after `npm ci` and `node node_modules/electron/install.js`:

```
npx electron spikes/p3-platform/main.cjs
```

On macOS, grant Screen Recording to the terminal or Electron when asked, then run it again.
Keep the machine's speakers on. The run takes about 20 s and writes
`spikes/out/p3-platform/<platform>.json`, which holds only the OS family and major version. It also
writes `cursor-always.png` and `cursor-never.png`: compare them by eye (is the pointer missing in
"never"?), then delete them.

| Check | What decides it | Feeds |
|---|---|---|
| `sources` | Is there a whole-desktop source (Windows: one id for all monitors)? How many displays? | Step 7 |
| `contentProtection` | `magentaFraction` near 0 when protected, above 0 when not: the controls can be hidden from capture | Step 6, `ui.excludeFromCapture` |
| `loopback` | `audioTrack: true` and a level well above silence (the 440 Hz tone) | Step 2, `audio.system` |
| `cursorHide` | The pointer is missing in `cursor-never.png` | Step 2, `capture.cursor.hide` |
| `cursorPolling` | Gaps between `getCursorScreenPoint()` samples at a 120 Hz timer (p95 under 10 ms is good enough for the fallback) | Step 4 |
| `tcc` (macOS) | Permission states before and after granting | Step 3 |

The click-to-video half of S11 (helper timestamps against a flash target) runs in step 4, once the
helper exists.

Dry run on Linux under Xvfb (2026-11-08), only to check the harness itself: every step ran.
Content protection had no effect (expected on Linux), polling gaps p50 8.5 ms / p99 9.0 ms, and
loopback returned an audio track with the tone — a hint that Chromium loopback may also work on
Linux X11, to look at later next to `pw-record`.
